# windtools 首版规格

日期：2026-10-08。状态：用户已确认并要求开始实现。下文工程默认均已随首版方案确认，作为实现依据；实测结果另行记录。

## 已确认的产品范围

首版提供两款工具：字符景观“风过原野”，以及本地 TUI 待办清单。Rust 实现，目标是 macOS、Linux、Windows 原生运行；允许 Unicode 字符，提供纯 ASCII 模式，普通等宽字体即可使用。两款工具采用不同视觉风格。

统一入口：运行 `windtools` 打开选择菜单；`windtools meadow` 与 `windtools todo` 直接进入对应工具。先完成两个工具，第三个等可体验后再评估。

待办数据是本机统一的个人清单，与启动目录无关。事项包含标题、可选备注、完成状态、可选提醒时间。首版处理单次事项，支持本地持久化和导出备份。

仅在 TUI 运行时发送系统桌面通知。退出程序后停止调度；关闭程序或系统休眠期间错过的提醒不补发。

## 待办界面

采用独立的事务清单风格：紧凑、清晰的文字层级，清单左对齐，时间和提醒状态右侧对齐。使用终端等宽字体，以字重、留白和选中标记区分层级；不增加持续动画。

配色依据：终端默认背景；草图主文字参考 #DCE4EA，次要文字 #97A6B1，选中项 #7BC8D6，提醒状态 #D8BE82，错误 #E58C8C。实现保留终端自身的正文前景色，以适配用户主题；RGB 模式的选中背景为 #1E343E。提供单色模式，状态同时用文字表示，不只靠颜色。

```text
windtools / 待办                     未完成 3

  未完成    全部    已完成

> [ ] 提交材料                      今天 15:00
  [ ] 整理会议笔记                  未设置提醒
  [ ] 预约体检                      提醒已错过

  提交材料
  备注：检查附件和收件人

  a 新增  e 编辑  Space 完成  / 搜索  ? 帮助
  Esc 返回菜单                       数据已保存
```

此草图为结构示意，实际按终端宽度和中文字符宽度排版。宽屏显示事项详情，窄屏切换到独立详情页；尺寸不足时显示明确提示。

## 交互与事项规则

- 支持新增、编辑、完成与恢复未完成、删除确认、标题搜索，以及未完成/全部/已完成视图。方向键和 j/k 均可移动；新增与编辑采用明确字段表单。
- 输入提醒时间使用本地日期与时间，表单显示实际日期；拒绝已过去或不存在的时间，避免保存一条立即错过的提醒。时区歧义显示给用户选择，不猜测。
- 完成或删除事项时取消尚未发送的提醒；修改为新的未来提醒时间时重新安排。恢复未完成状态不会自动重复发送旧提醒，可重新设置时间。
- 错过提醒只影响通知，不自动完成或删除事项。清单显示“提醒已错过”，用户可改为新的未来时间。
- 系统通知提交成功显示“已提交系统”；调用失败显示“发送失败”及原因。系统返回成功不等于用户已阅读。通知操作不阻塞清单操作；不自动反复弹窗。
- 修改后立即保存，写入成功后才显示“数据已保存”。保存失败时保留编辑内容、说明原因，并允许重试；异常退出后保留此前已提交的修改。
- 备份导出为带格式版本的 JSON，包含事项和提醒状态；提供导入恢复入口及变更预览，恢复前保留原数据备份。

## 统一入口中的提醒

提醒由整个 windtools TUI 会话调度。停在菜单、进入待办、打开表单，或切换到风过原野，都继续处理尚未错过的提醒；退出 windtools 才停止。

例：15:00 设置提醒，14:59 从待办切到原野，15:00 仍提交系统通知。若 14:59 退出、15:05 重开，旧提醒标为已错过，不补发。休眠后恢复同样跳过已错过的提醒。正常调度和系统提交存在少量延迟，不将其当作离线补发。

## 风过原野

一个完整的固定镜头场景，包含远山、草海和有数量上限的飘叶。左右键改变风向，空格触发阵风，p 暂停；Esc 回菜单。支持种子复现、Unicode 与 ASCII 字符表、小窗口适配；先打磨这一幅景观。

## 技术与交付

采用一个 Rust 工程与单一可执行文件，按应用入口、待办领域、存储、提醒、平台通知及原野场景划分模块。终端框架为 Ratatui + Crossterm；依赖版本在实现时按当前兼容性锁定。

本地存储使用 SQLite，以事务提交事项和提醒状态；路径遵循各平台用户数据目录。JSON 用于导出交换。多个实例对同一提醒的提交需要协调，不能因重复打开界面就重复弹窗。

待办以输入、数据变更和提醒事件驱动绘制，空闲时等待。原野默认目标 30 FPS，暂停后停止动画刷新；只向终端输出变化单元。提供颜色降级与单色模式，键盘操作覆盖全部首版功能。SSH/tmux 中验证字符界面；系统通知需有可用的桌面通知服务。

先完成本机可运行版与安装说明，再配置三平台构建和发布产物。跨平台构建成功、终端交互通过和桌面通知实际显示分别记录；不能仅凭本机测试宣称三平台已验收。

## 完成标准

- 待办：新增/编辑/完成/删除、退出后重开、备份恢复形成闭环；中文输入与窄屏可用。
- 提醒：运行中到点、完成/删除取消、修改时间、错过不补发、失败反馈及重复实例行为有针对性验证。
- 原野：画面与风向/阵风互动可体验，暂停、窗口变化和退出恢复终端均正常。
- 性能：release 构建，记录 120×40 与 240×80 场景的 CPU、内存和帧耗时；用 10,000 件待办验证滚动、搜索和输入响应。原野 30 FPS 的帧预算约 33.3 ms，输入响应目标为 100 ms 内；这些是验收目标，尚非已测成绩。
- 文档：明确命令、数据位置、备份恢复方式、提醒生效范围，以及实际通过验证的平台。
