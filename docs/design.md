# windtools 设计访谈

更新：2026-10-08。状态：用户已确认首版规格并要求开始实现；见 `docs/spec-v1.md`。

## 已确认

- 项目名称为 **windtools**。
- 使用 Rust，重视性能。
- 目标体验同时覆盖开发者日常使用，以及终端玩家、内容创作者的视觉展示。
- 产品包含炫酷的终端效果、字符画与实用价值。
- 首版支持 macOS、Linux、Windows 原生运行，以现代终端为基线。
- 先完成两个完整工具，第三个根据效果再定。
- cmatrix、genact 是参考对象；首发需要自己的特点。
- 首发组合为一款纯视觉的观赏工具，加一款有明确用途的实用工具；两款工具采用不同视觉风格。
- 观赏工具视觉方向：风、粒子、山水等生成艺术。待办采用独立的事务清单风格。
- 使用字符绘制，允许 Unicode 点阵和色块，并提供纯 ASCII 模式；普通等宽字体即可运行。
- 观赏工具选择“风过原野”：草海、远山、飘叶；方向键改变风向，空格掀起阵风。
- 实用工具选择 TUI 待办清单，要求保存到本地并能够通知用户。
- 待办仅在 TUI 正在运行时发送系统桌面通知；退出后不继续提醒。
- 首版支持单次待办：标题、可选备注、完成状态、可选提醒时间。
- 同一台电脑共用一份个人清单，从任何目录打开均访问同一份数据，并可导出备份。
- 关闭 TUI 或系统休眠期间错过的提醒，不再补发。
- 统一使用 `windtools` 入口：直接运行打开工具选择菜单，`windtools todo`、`windtools meadow` 可直接进入对应工具。

## 访谈结论与实现

待办围绕快速记录、查看与完成、指定时间提醒构成完整流程，独立的文字清单不混入原野景观。错过的提醒显示“已错过”，未完成事项继续保留，可重新设置未来时间。
